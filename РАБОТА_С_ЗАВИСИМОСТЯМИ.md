# 📦 Работа с зависимостями проекта

## 🎯 Зачем виртуальное окружение?

Виртуальное окружение (`venv`) изолирует зависимости проекта от системных библиотек Python. Это гарантирует:

- ✅ **Нет конфликтов** с другими проектами
- ✅ **Стабильные версии** зависимостей
- ✅ **Чистая сборка** без лишних пакетов
- ✅ **Портативность** - все зависимости в папке проекта

## 🚀 Первоначальная настройка

### Перед первой сборкой запустите:

**Windows:**
```
ОБНОВИТЬ_ЗАВИСИМОСТИ.bat
```

**macOS:**
```
Дважды кликните: ОБНОВИТЬ_ЗАВИСИМОСТИ.command
```
или в терминале:
```bash
./ОБНОВИТЬ_ЗАВИСИМОСТИ.sh
```

**Linux:**
```bash
./ОБНОВИТЬ_ЗАВИСИМОСТИ.sh
```

Этот скрипт:
1. Создаст папку `venv/` с виртуальным окружением
2. Установит все зависимости из `requirements.txt`
3. Сохранит точные версии в `requirements-lock.txt`

## 🔄 Обновление зависимостей

Если нужно обновить зависимости до последних версий:

**Просто запустите тот же скрипт:**
```
ОБНОВИТЬ_ЗАВИСИМОСТИ.bat  (Windows)
./ОБНОВИТЬ_ЗАВИСИМОСТИ.sh  (macOS/Linux)
```

Скрипт автоматически:
- Обновит pip
- Обновит все пакеты из `requirements.txt`
- Сохранит новые версии в `requirements-lock.txt`

## 📋 Структура файлов

```
проект/
├── venv/                    # Виртуальное окружение (создается автоматически)
│   ├── bin/                 # Исполняемые файлы (macOS/Linux)
│   ├── Scripts/             # Исполняемые файлы (Windows)
│   └── lib/                 # Установленные пакеты
├── requirements.txt         # Список зависимостей (минимальные версии)
├── requirements-lock.txt    # Точные версии (создается автоматически)
└── ОБНОВИТЬ_ЗАВИСИМОСТИ.*   # Скрипты обновления
```

## 🔧 Ручное управление venv

### Активация виртуального окружения

**Windows:**
```cmd
venv\Scripts\activate.bat
```

**macOS/Linux:**
```bash
source venv/bin/activate
```

### Деактивация

```bash
deactivate
```

### Установка пакета вручную

После активации venv:
```bash
pip install имя_пакета
```

### Просмотр установленных пакетов

```bash
pip list
```

### Экспорт текущих версий

```bash
pip freeze > requirements-lock.txt
```

## ⚠️ Важные замечания

1. **Папка `venv/` не попадает в git** (указана в `.gitignore`)
2. **Не удаляйте `venv/`** - это ваше изолированное окружение
3. **После клонирования проекта** запустите `ОБНОВИТЬ_ЗАВИСИМОСТИ.*`
4. **Скрипты сборки** автоматически используют `venv/` если он существует

## 🎯 Автоматическое использование

Все скрипты сборки (`СБОРКА_*.bat/sh`) автоматически:
- ✅ Проверяют наличие `venv/`
- ✅ Создают его, если не существует
- ✅ Активируют перед сборкой
- ✅ Деактивируют после сборки

**Вам не нужно вручную активировать venv перед сборкой!**

## 🔍 Решение проблем

### Ошибка: "venv не найден"

**Решение:** Запустите `ОБНОВИТЬ_ЗАВИСИМОСТИ.*` один раз

### Ошибка: "Конфликт версий"

**Решение:** 
1. Удалите папку `venv/`
2. Запустите `ОБНОВИТЬ_ЗАВИСИМОСТИ.*` заново

### Ошибка: "Пакет не найден"

**Решение:**
1. Активируйте venv вручную
2. Запустите `pip install -r requirements.txt`
3. Или запустите `ОБНОВИТЬ_ЗАВИСИМОСТИ.*`

## ✅ Итог

**Для работы с проектом:**
1. Первый раз: запустите `ОБНОВИТЬ_ЗАВИСИМОСТИ.*`
2. Для сборки: запустите `СБОРКА_*.bat/sh` (venv используется автоматически)
3. Для обновления: запустите `ОБНОВИТЬ_ЗАВИСИМОСТИ.*` снова

Все зависимости хранятся в папке `venv/` и не конфликтуют с системными!
